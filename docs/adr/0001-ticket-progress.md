# ADR 0001　両方の盤面が一つのチケット進捗を使う

**状態**　合意済み（プロダクト方針の範囲）。対象は[要求 R3・R4](../REQUIREMENTS.md)。DBの列構成やAPI形式は未決。

**背景**　同じチケットを案件別・横断の両方で扱う。個人が今日の仕事を選ぶ操作もある。三者が別々に進捗を持つと、チームに報告するための転記が必要になる。

**選択肢**　各盤面にカードの状態を保存して同期する案と、チケットの具体状態を各盤面で表示する案を比較した。前者は盤面ごとに自由な列を定義しやすいが、同期失敗時に正式な進捗が定まらない。

**決定と根拠**　進捗の単位はチケットとする。案件別盤面と横断盤面からの変更は同じ遷移を表す。個人が注目票を選んでも共有の進捗は変わらない。現行の案件別盤面もチケットを更新しており、この操作を活かせる。[現行盤面](../../frontend/src/pages/KanbanPage.tsx)

**影響**　両画面と詳細の再表示、共有の遷移検証、複数候補から具体状態を選ぶ操作が必要になる。標準列とカスタム状態の対応や完了レビューの表現はQ3で決める。

今後のADRは背景・選択肢・決定または提案・根拠・影響を記し、提案中／合意済み／置換済みの状態を明示する。置換時は後続の判断へのリンクを残す。
