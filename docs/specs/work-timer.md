# 個人の作業タイマーと工数訂正

**仕様案**。対象は[要求 R6・R7、判断点 Q5・Q6](../REQUIREMENTS.md)。既存の稼働タイマーは勤務開始・終了を表す。ここで扱う単位は「誰が、どの作業を、いつからいつまで行ったか」。本人が作業を選ぶだけで実績を残す。

## 入出力と権限

| 操作 | 前提・入力 | 期待結果 |
|---|---|---|
| 開始・切替 | 認証済み本人。対象は権限のあるチケット、または「その他業務」。 | 自分の実行中の対象・開始時刻を返す。別対象なら同じ時刻で前を閉じ次を開始。同じ対象の開始を再送しても区間を増やさない。 |
| 現在・停止 | 本人。停止対象の実行中区間を識別する。 | 共通ヘッダーやダッシュボード、再ログイン後も現在の対象を表示。停止時に終了時刻を確定。対象なしなら停止済みと区別できる応答を返す。 |
| 訂正 | 本人が自分の区間、正しい開始・終了を指定。 | 停止忘れを直せる。訂正前後と実行者・時刻を記録。締め期間の変更は権限のある解除操作と関連づける。 |
| 集計 | 対象票または利用者と期間。サーバーが閲覧範囲を判定。 | チケット工数はその票の作業者別区間から計算。「その他」は個人実績に含める。稼働打刻、進行中状態の滞在時間を加算しない。 |

## 例外と実装候補

- 推奨案はサーバー時刻、利用者あたり未終了1件のDB制約、切替の一括コミット。切替先に権限がない場合、前の計時を維持する。複数端末の古い停止要求が新しい区間を止めないよう、対象区間または版を照合する。
- 開始以後に案件を離れた利用者にも、自分の進行中区間を停止できる経路を残す。失効した閲覧権限で案件情報を再表示しない。訂正で負の時間や同一人の重複区間を作らない。
- 閉じた月にかかる変更は拒否し、解除後の訂正を履歴に残す。日別承認との関係、月跨ぎの配賦、閲覧者と親票の扱いはQ5・Q6に従う。
- 対象外はPC操作の推定、工数分析画面、既存の状態履歴からの実績の推計。打刻外のチケット計時の可否を、この仕様案で決め打ちしない。

## 受け入れ例

1. 画面をまたいで A を10:00に開始、10:15に B、10:25に停止。Aに15分、Bに10分が残り、稼働打刻は変化しない。
2. 未打刻で「その他」を計時できる。チケットの作成・加算は発生しない。
3. 旧区間の停止再送と別端末からの切替が重なっても、履歴に重複がなく、最新の正常な開始を取り消さない。切替失敗時も半端な終了を残さない。
4. 本人以外の訂正と締めた期間への訂正を拒否。解除後の本人訂正から再締めまで、対象期間と変更者をたどれる。
