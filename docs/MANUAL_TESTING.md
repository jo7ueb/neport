# フロントエンド手動テスト手順書

対象: ログイン・プロジェクト・チケット・かんばん・マイルストーン・
管理者ユーザー管理・ガントチャート・作業時間・日報（全画面）

## 事前準備

`docker-compose.yml` の `frontend` サービスは `frontend/Dockerfile` で
React アプリをビルドし、そのまま配信する構成になっている。
Node.js をローカルに入れなくても以下だけで完結する:

```bash
docker-compose up -d --build
```

→ ブラウザで http://localhost:8880 を開く（`/api/*` は同じコンテナ内で
バックエンドにプロキシされる）

## テストケース

### 1. 未ログイン状態のアクセス制御

- [ ] ブラウザのシークレットウィンドウ（またはCookie削除後）で `http://localhost:8880/` にアクセスする
- [ ] `/login` にリダイレクトされることを確認する

### 2. ログイン

事前にテストユーザーが必要な場合は作成しておく:
```bash
curl -X POST http://localhost:3000/api/v1/users \
  -H "Content-Type: application/json" \
  -d '{"email":"test@example.com","password":"TestPassword123","display_name":"テストユーザー"}'
```

- [ ] `/login` でメールアドレス・パスワードを入力してログインする
- [ ] 成功後、ダッシュボード画面（`/`）に遷移することを確認する
- [ ] 誤ったパスワードでログインを試み、エラーメッセージが表示されることを確認する

### 3. ページリロード時のログイン状態維持

- [ ] ログイン後、ブラウザをリロード（F5）する
- [ ] ログイン画面に戻らず、ダッシュボードが表示されたままであることを確認する
  （`GET /api/v1/auth/me` によるセッション復元の確認）

### 3.5 ダッシュボード

- [ ] ナビの「ダッシュボード」（ロゴクリックでも可）で `/` を開く
- [ ] 作業時間ウィジェットが表示され、`/work` と同じボタン操作
      （作業開始・作業終了の2つのみ）ができることを確認する
- [ ] 自分が担当者で `in_progress` のチケットが「進行中のチケット」に
      表示されることを確認する（プロジェクト名・締切超過時の赤字表示も確認）
- [ ] 担当外・他ステータスのチケットが表示されないことを確認する
- [ ] 「日報を書く」ボタンで `/daily-report` に遷移することを確認する
- [ ] 「プロジェクト一覧」リンクで `/projects` に遷移することを確認する

### 4. プロジェクト作成・一覧

- [ ] ナビの「プロジェクト」（`/projects`）を開く
- [ ] フォームから新規プロジェクトを作成する
- [ ] 作成したプロジェクトが一覧に表示されることを確認する
- [ ] プロジェクト名をクリックし、チケット一覧画面に遷移することを確認する
- [ ] プロジェクトを26件以上作成し、一覧下部のページングで「表示件数」を
      10/25/50/100 に切り替えると1ページあたりの件数が変わることを確認する
- [ ] 「次へ」「前へ」でページが送れ、表示中の件数（例: `1-25件 / 全30件`）が
      正しいことを確認する

### 5. チケット作成（親子構造）

- [ ] チケット一覧画面で「新規チケット」フォームからチケット A を作成する
- [ ] チケット A の詳細画面を開く
- [ ] 「子チケット」フォームから子チケット B を作成する
- [ ] 子チケット一覧に B が表示されることを確認する
- [ ] B の行の展開ボタン（▸）をクリックし、孫チケットが遅延取得されることを確認する
  （さらに孫チケット C を作れば展開時に表示されることも確認できる）

### 6. チケット詳細編集

- [ ] チケット詳細画面でタイトル・概要・ステータス・担当者・締切日を変更し「保存」する
- [ ] 保存後、変更内容が画面に反映されることを確認する
- [ ] 「親チケットID」欄に孫チケットのIDを入力して保存し、
      循環エラー（400 "this move would create a cycle..."）がフォーム上に表示されることを確認する
- [ ] 子チケットを持つチケットの詳細画面で「削除」ボタンを押し、確認ダイアログで
      子チケット件数が表示されることを確認する。OKすると一覧画面に戻り、削除された
      チケット・子チケットのURLに直接アクセスすると404になることを確認する

### 7. 締切超過ハイライト

- [ ] 締切日を昨日以前の日付に設定して保存する
- [ ] ステータスが `open` または `in_progress` の場合、チケット一覧・詳細画面の該当行が
      赤くハイライトされることを確認する
- [ ] ステータスを `done` に変更すると赤色ハイライトが消えることを確認する

### 8. コメント

- [ ] チケット詳細画面のコメント欄からコメントを投稿する
- [ ] 投稿したコメントが一覧に反映されることを確認する（自分の表示名が author として記録されていることは
      `GET /api/v1/tickets/:id/comments` のレスポンスの `author_id` で裏付けられている）
- [ ] コメントを11件以上投稿し、コメント欄下部のページングで件数切り替え・
      ページ送りが機能することを確認する

### 9. 依存関係

- [ ] 別のチケット（例: チケット D）を作成する
- [ ] チケット A の詳細画面で「後続チケットとして追加」を選び、D のIDを入力して追加する
- [ ] predecessors/successors リストに反映されることを確認する
- [ ] D → A のような循環を作る依存関係を追加しようとし、エラーメッセージが表示されることを確認する
- [ ] 追加した依存関係の「削除」ボタンでリストから削除できることを確認する

### 10. フィルタ・ページング

- [ ] チケット一覧画面でステータス・担当者・締切超過のフィルタを切り替え、
      表示されるチケットが絞り込まれることを確認する
- [ ] フィルタを変更すると表示ページが1ページ目に戻ることを確認する
- [ ] チケットを26件以上作成し、一覧下部のページングで件数切り替え
      （10/25/50/100）・ページ送りが機能することを確認する
- [ ] ページング導入後も、かんばんボード・WBS・ダッシュボードの「進行中の
      チケット」に全チケットが表示されたまま（一部が欠落しない）であることを
      確認する（内部的に「全件取得」を使う画面の回帰確認）

### 11. ログアウト

- [ ] 画面右上の「ログアウト」ボタンを押す
- [ ] `/login` にリダイレクトされることを確認する
- [ ] ブラウザの戻るボタンや `/` への直接アクセスで、再度 `/login` にリダイレクトされることを確認する
      （セッションが正しく破棄されていることの確認）

### 12. かんばんボード

- [ ] チケット一覧画面上部の「かんばん」タブからかんばん画面に遷移する
- [ ] カラム追加フォームで `open`/`in_progress`/`done`/`closed` に対応する
      4つのカラムを作成する
- [ ] 同じ対応ステータスで重複してカラムを作成しようとし、エラーになることを確認する
- [ ] チケットカードをドラッグして別のカラムにドロップし、チケットの
      ステータスが変わる（カード一覧・チケット詳細双方で確認）ことを確認する
- [ ] カラム右上の「×」で削除できることを確認する
- [ ] カラム名のヘッダー部分をクリックしてリネームできることを確認する
      （Enterまたはフォーカスを外すと保存、Escapeでキャンセル）

### 13. マイルストーン

- [ ] 「マイルストーン」タブから作成フォームで新規マイルストーンを作成する
- [ ] 作成したマイルストーンが一覧に表示されることを確認する
- [ ] 一覧の「編集」ボタンで名前・締切日・説明を変更し、保存が反映されることを確認する
- [ ] チケット詳細画面の「マイルストーン」セレクトで紐付けて保存し、反映されることを確認する
- [ ] マイルストーンを削除し、紐付けていたチケットの `milestone_id` が
      「未設定」に戻ることを確認する（`ON DELETE SET NULL` の確認）

### 14. 管理者ユーザー管理

事前準備: `.env` に `ADMIN_EMAIL`/`ADMIN_PASSWORD`/`ADMIN_DISPLAY_NAME` を
設定した状態で初回起動すると、`users` テーブルが空の場合に限り管理者
アカウントが自動作成される（2回目以降の起動では作成されない）。

- [ ] 起動時に指定した `ADMIN_EMAIL`/`ADMIN_PASSWORD` でログインでき、
      `role: "admin"` になっていることを確認する
- [ ] 一般ロールのユーザーで `/admin/users` にアクセスし、
      「このページは管理者のみ利用できます」と表示されることを確認する
      （ナビにも「ユーザー管理」リンクが出ないことを確認）
- [ ] 管理者アカウントでログインし、`/admin/users` が閲覧できることを確認する
- [ ] ユーザー作成フォームから、ロール（一般/管理者）を選んで新規ユーザーを
      作成できることを確認する（一般ユーザー・2人目の管理者どちらも作成できる）
- [ ] 一覧の「停止」「再開」「削除」ボタンがそれぞれ機能することを確認する
- [ ] 自分自身の行には操作ボタンが表示されず「自分自身は操作できません」と
      表示されることを確認する（誤って自分を停止・削除できない安全策）
- [ ] 一般ユーザーでログインした状態でブラウザの開発者ツール等から
      `POST /api/v1/users` を直接叩いても 403 になることを確認する
      （UI側のガードだけでなくバックエンド側でも防御されていることの確認）
- [ ] ユーザーを26件以上作成し、一覧下部のページングで件数切り替え・
      ページ送りが機能することを確認する
- [ ] ページング導入後も、チケット一覧・チケット詳細・WBSの担当者
      ドロップダウンに全ユーザーが表示されたままであることを確認する
      （内部的に「全件取得」を使う画面の回帰確認）
- [ ] 一覧の「パスワードリセット」ボタンを押すと、一時パスワードが
      画面上部のバナーに表示されることを確認する
- [ ] 表示された一時パスワード・対象ユーザーのメールアドレスで、別の
      ブラウザ（またはシークレットウィンドウ）からログインできることを確認する
- [ ] リセット対象ユーザーが元々ログインしていた場合、そのセッションが
      無効化される（リロードするとログイン画面に戻る）ことを確認する
- [ ] ユーザー作成フォームで8文字未満、または英字か数字のどちらかしか
      含まないパスワードを入力すると、エラーになることを確認する
- [ ] 一般ユーザーの行のロールセレクトを「管理者」に変更すると、即座に
      昇格することを確認する（そのユーザーで再ログインし `/admin/users` に
      アクセスできることを確認する）。逆に管理者→一般への降格も確認する
- [ ] 自分自身の行にはロールセレクトが表示されず、テキスト表示のみで
      あることを確認する

### 14.5 アカウント設定（パスワード変更）

- [ ] ヘッダーの「アカウント設定」リンクから `/account` に遷移できることを確認する
- [ ] 現在のパスワードを間違えて入力すると、エラーメッセージが表示されることを確認する
- [ ] 8文字未満、または英字か数字のどちらかしか含まない新パスワードを
      入力すると、エラーになることを確認する
- [ ] 正しい現在のパスワードと新しいパスワードを入力すると変更に成功することを確認する
- [ ] 一度ログアウトし、新しいパスワードでログインできることを確認する
      （旧パスワードではログインできないことも確認する）
- [ ] 別のブラウザ（またはシークレットウィンドウ）で同じアカウントに
      ログインした状態でパスワードを変更し、変更後にそちらのブラウザを
      リロードするとログイン画面に戻る（セッションが無効化される）ことを
      確認する。変更を行った側のブラウザは操作を続けられることも確認する

### 14.6 言語切り替え（i18n）

- [ ] 新規登録・初回ログイン直後は日本語UIで表示されることを確認する
      （`users.locale` の既定値は `ja`）
- [ ] `/account`（アカウント設定）の「言語 / Language」セレクトで `English` を選択すると、
      即座にヘッダー・ナビ・ボタン・フォームラベル等、画面全体が英語表示に切り替わることを
      確認する（確認ダイアログは無し）
- [ ] 英語表示のままページをリロードしても英語表示が維持されることを確認する
      （`GET /auth/me` のレスポンスに含まれる `locale` を見て復元しているため）
- [ ] 一度ログアウトし、同じアカウントで再ログインしても英語表示が維持されることを確認する
      （選択した言語がDB（`users.locale`）に保存されているため、別ブラウザ・別デバイスから
      ログインしても同じ言語で表示される）
- [ ] 主要画面（ダッシュボード・プロジェクト一覧・チケット一覧/詳細・かんばん・
      マイルストーン・ガント・WBS・作業時間・日報・管理者ユーザー管理・アカウント設定・
      ログイン画面）をそれぞれ日本語/英語の両方で開き、訳抜け（日本語モードで英語が残る、
      またはその逆）が無いことを確認する
- [ ] チケットのステータス（未着手/進行中/完了/クローズ）が、一覧・詳細・WBS・かんばんの
      各画面で選択中の言語に応じたラベルで表示されることを確認する
- [ ] わざとエラーを起こす操作（弱いパスワードでのユーザー作成、自分自身のロール変更など）
      を行い、エラーメッセージが選択中の言語で表示されることを確認する
- [ ] 言語を `日本語` に戻すと画面全体が日本語表示に戻ることを確認する

### 15. ガントチャート

- [ ] チケットに開始日・終了日（または締切日）を設定した状態で「ガント」タブを開く
- [ ] チケットがバーとして表示されることを確認する
- [ ] 依存関係を設定したチケット同士に依存線が表示されることを確認する
- [ ] 開始日・終了日が未設定のチケットも、作成日を起点に何らかのバーが
      表示される（フォールバック挙動）ことを確認する

### 15.5 WBS（作業分解構造）

- [ ] 「WBS」タブを開き、チケットの親子構造がインデント付きの表として
      一覧表示されることを確認する
- [ ] タイトルのセルをクリックして編集し、フォーカスを外す（blur）と
      保存されることを確認する（再読み込みしても反映されている）
- [ ] ステータス・担当者・開始日・終了日・締切日の各セルも同様に
      クリック編集→保存できることを確認する
- [ ] セル編集中に Escape キーを押すと、保存されずに編集がキャンセル
      されることを確認する
- [ ] 行の「+ 子タスク追加」からタイトルを入力して追加すると、
      その行の直下に子タスクとして追加されることを確認する
- [ ] 表上部の「+ ルートタスク追加」からルート直下にタスクを追加できる
      ことを確認する
- [ ] 兄弟行が存在する行で「→」（インデント）を押すと、直前の兄弟の
      子になることを確認する（チケット詳細画面で親子関係を確認）
- [ ] 子になっている行で「←」（アウトデント）を押すと、親と同じ階層
      （祖父母の子、ルート直下の場合はルート）に戻ることを確認する
- [ ] 最初の兄弟行では「→」、ルート直下の行では「←」がそれぞれ
      無効化されていることを確認する

### 16. 作業時間

- [ ] ナビの「作業」から `/work` を開く
- [ ] 「作業開始する」を押し、開始時刻が記録されることを確認する
- [ ] 「作業終了する」を押し、終了時刻が記録されることを確認する
- [ ] 「作業開始する」→「作業終了する」をもう一度繰り返し、
      同じ日に複数回の作業記録ができる（中抜けボタンは無く、終了→再開始で
      表現する）ことを確認する
- [ ] `/work` の表示で「作業回数」が2件になっていることを確認する
- [ ] 日報を提出しない状態で作業を終了した状態のまま、状態が `invalid` に
      なることを確認する
- [ ] 「月次一覧」（`/work/monthly`）画面で当日の記録
      （最初の開始・最後の終了・作業回数・実働時間・状態）が表示されることを確認する
- [ ] （時間があれば）作業開始した状態で日付が変わるのを待たず、
      作業を終了せずに翌日以降になった場合でも「現在作業中」表示のまま
      「作業終了する」ボタンが機能する設計になっていることをコードで確認
      （日付をまたぐ作業のカバー。実運用でのみ確認可能なため必須ではない）

### 17. 日報

- [ ] ナビの「日報」から `/daily-report` を開く
- [ ] 本日操作したチケット（コメント・ステータス変更等を行ったもの）が
      自動収集リストに表示されることを確認する
- [ ] ALKPT（Achievement/Leftover/Keep/Problem/Try）を入力して提出する
- [ ] 提出成功メッセージが表示されることを確認する
- [ ] 作業時間画面に戻り、直前に `invalid` だった当日の状態が
      `valid` に変わっていることを確認する（月次一覧でも確認可。保存された

## 既知の制限（今回のスコープ外）

- 依存関係の削除UIは未実装（一覧APIが `dependency_id` を返さないため）
- CSRF検証はバックエンド側が未実装のため、フロントは送出のみで実質的な効果はまだない
